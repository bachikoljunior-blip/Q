# 音声・映像・再生の確認

## 声と編集

日本語を扱える利用可能な音声機能を選び、複数役なら短い掛け合いで声を比較する。提供元、声の指定、台詞の範囲を記録する。古い接続エラーやプラン制限を引き継ぐだけで利用不可と決めない。一方、残量不足や拒否を、権限・課金を回避して突破しない。

全文の音声があるか、各台詞の始めと終わりが欠けていないか確認する。プレビュー専用URLや秒数制限があるサービスでは、実際に出た長さを調べる。音声認識は文字の照合に使い、アクセントや芝居の合格判定には使わない。

切り貼りの後に、台詞、字幕、話者名、口の動き、オチの表示を合わせる。音量を役ごとに整え、BGMが台詞を邪魔しないようにする。確認用の短いクリップも、次の台詞の頭を半端に含めず、文末まで聞ける区切りで作る。

## 納品ファイルを調べる

FFmpegとffprobeがある環境では、次を実行する。

```bash
python3 scripts/inspect_media.py /absolute/path/to/final.mp4 --output /absolute/path/to/media-check.json
```

このコマンドのパスはスキルを基準に解決する。スクリプトは読み取り検査のみで、元動画を変更しない。指定したレポートが既存なら上書きするので、新しい版の検査先を使う。Python標準ライブラリ、FFmpeg、ffprobeが必要。

確認する値は、全編のデコード、映像・音声の形式と長さ、音声の実在、音量、音声ピーク、左右の相関とモノラル合成時の変化、MP4の先頭からの再生に関係する配置。計測値はファイルのSHA-256とともに残す。診断の終了コード0は、映像が面白い・端末で再生できたという意味ではない。

左右の解析は16kHzに変換した診断音声で行う。細かい音質評価や高域の位相測定の代用にはしない。多チャンネル音声は左右検査の対象外として記録する。LUFSとtrue peakはFFmpegによる全音声の測定を別に記録する。

## イヤホンでしか聞こえない場合

1. ユーザーが受け取った版を特定して検査する。音声トラックがない、無音、片側だけ、逆相による打ち消し、極端な低音量などを区別する。
2. 相関が強い負の値でモノラル合成時に大きく減る場合は、逆相を候補とする。ただし検査結果だけで、端末の症状の原因を確定しない。元からモノラルなら左右の逆相は原因候補にならない。
3. 異常がなければ、その結果を伝えたうえで、必要に応じてモノラルAAC-LCのMP4や独立した短いMP3を用意する。無音になった理由を証明できないのに「モノラル化で修理完了」と言わない。
4. アプリ内で失敗する場合は、ダウンロードしたファイルを別の標準プレーヤーで開く方法を提示する。端末の出力先や消音設定の手順が必要なら、その端末の現行公式案内を確認する。端末を直接確認していなければ、実機確認待ちと記録する。

## 互換性と実聴

一般的なMP4の互換候補はH.264／yuv420p／AAC-LC、適切なサンプルレート、faststart。元の解像度やフレームレートに合わせて書き出し、無意味な拡大を品質向上と呼ばない。問題がなければ既存の良好な形式を維持する。

会話主体なら-16 LUFS付近、符号化後もピークに余裕を残す設定などを目安にできるが、作品や再生先に合わせる。目安の達成を聞きやすさの証明にしない。大きくするだけで無音原因が解決するとは限らない。サンプルピークとtrue peakを区別する。

全編の自動デコードに加え、実際の書き出し映像で重要な場面を見て、文字の切れ・字幕の重なり・話者の取り違えを確認する。縦動画では、人物や字幕を縦画面用に配置し、アプリのボタンや説明欄に重なりにくくする。

実聴できない環境では、その限界を明示する。発音、抑揚、演技、役の聞き分けを未確認のまま消さず、他の制作作業を進める。反応を得たら該当箇所を直し、確認結果を更新する。
