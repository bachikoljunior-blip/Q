# Q — 灰の巡礼

スマートフォン向けオープンワールドアクションRPG。独自のファンタジー世界「灰冠の地」を探索する、第一章「残り火の谷」の開発版です。

世界の火を集めた王冠は、王を失ったまま燃え続けている。巡礼者は三つの灯火を取り戻し、北の門に待つ番人を倒し、火の行く先を選びます。

**現段階は初期実装です。ユーザーが指定した10作品と同等の品質に達したとは判断していません。** 現在の確認範囲、未達項目、制作の続きは [制作状況](docs/PROJECT_STATE.md) に記録しています。

## 遊ぶ

- [プレイ版を開く](https://q-ash-pilgrim.juurooo.chatgpt.site)（所有者限定）。
- タイトルは巡礼者・北門・炎の王冠のオリジナル画と灰・霧の演出で先に表示し、「旅を始める」「旅をつづける」またはセーブ読込を選んだ時点で3D世界を読み込みます。「音を入れる」でタイトル曲を聴けます。音は操作後に開始し、タイトルへ戻ると3D描画と音を休止します。動きを減らす端末設定にも対応します。
- PCでは [単体起動版](release/Q-ash-pilgrim.html) をダウンロードし、WebGL 2対応ブラウザーで開くこともできます。単体版は外部CDN・画像・音声への通信を必要としません。
- スマートフォンはプレイ用URLから開いてください。横向き・縦向きのレイアウトを実装しています。ストア向けのAPK/IPAはまだありません。
- セーブは端末のブラウザーに保存します。消費したスタミナ・残火、回復や攻撃の途中、敵の残り体力と矢も引き継ぎます。旧バージョンのセーブも読込可能です。ひとつ前の正常な記録を残し、保存が壊れた場合に復旧します。タイトルからファイルを読み込むこともできます。「旅の記録」からJSONで書き出し・読み込みができます。

## 実装済みの遊び

- 鐘の報告後の「炉を囲む約束」と、旅人へ薬を届けた後の「夜道の目印」。二人に声をかけると実際に集まり、相談の選択で会話・薬棚・灯りが変わります。離れた場所や危険下では中断し、途中保存から続きを話せます。相談のある人物にはしるしが付き、会話画面で参加者・現在の話者・進み具合を確認し、既に読んだ話を読み返せます。相談中は参加者が巡礼者へ向き、二人を見渡せる会話視点になります。閉じると通常の視点へ戻ります。

- 高低差のある約740×502 mの移動範囲、集落、森、水殿、廃塔、北の門、西の白塩の段丘。遠景の山脈、川、橋、草木、昼夜の移り変わり。805本の木の幹は見た目と同じ位置で移動・矢・カメラを遮ります。
- 入力の先行受付、剣・槍・大剣の三段連撃、スタミナ、無敵時間付き回避、方向とタイミングを使う受け流し、跳躍、範囲攻撃「残火」、対象の注視。武器ごとに射程・攻撃速度・消費・攻撃範囲が変わります。攻撃の予兆中は、自由カメラの実投影で画面外も分類し、同時の脅威をすべて判定したうえで「待機」または次の防御操作を1つだけ示します。多数の矢は同じ呼出しでまとめて予測し、全候補を捨てずに警告します。地形は従来どおり60 Hz区間で調べ、人物または障害物への接触候補を含む区間は実ゲームと同じ接触順で確定します。タッチ・キーボード・パッドの同一フレーム入力は1操作へ調停し、表示中の防御を優先します。
- 獣、兵士、狙いを定めて矢を放つ弓兵、体力によって行動が変わる地域ボス。攻撃の予兆、ひるみ、障害物を迂回する追跡、帰還。敵は従来30体とvault番兵4体の合計34体。
- 熾火・潮錆・風蝕・苔影のvault四か所。環状壁の入口から入り、theme別の番兵を倒して石板の記憶を受け取ります。進入・撃破・取得は保存され、番兵はguard / prowl / charge / releaseの4姿勢、各vaultは固有の石材textureとambient、共有6効果音を使います。
- 11個の宝箱、50個の露草、巡礼の遺物。経験値、レベル、安全な灯火での三系統の強化、敵のいない場所での霊薬の調合。霊薬は飲み終わると回復し、途中の被弾・回避で中断します。
- 灯守ミラとの会話と遺物の配達、三つの灯火の奪還、休息・高速移動、死亡と再出発、二つの章末選択。章を終えても探索可能。
- 渡し守セナの分岐クエスト「川の向こうの約束」。橋を渡って東岸の荷車を奪還し、薬草の届け先を選ぶと、霊薬の効果・補充数・そこに暮らす人、会話、集落や野営地の様子が変わります。旅人側の薬箱は安全なときに霊薬を4本まで補充できます。
- 鍛冶師レンと薬師イオは時間帯に応じて仕事場や灯火へ歩き、敵が近づくと避難します。近づくと足を止めて話せます。集落を選ぶと回復した人と荷運びが生活へ戻り、旅人を選ぶと橋の野営地に巡回者が現れます。
- 探索クエスト「風の入らない炉」。西の三響の祠で碑文を読み、鳥・雨・星の鐘を順に鳴らします。音を使わず文字としるしでも解けます。レンに報告すると「風渡りの鈴」を受け取り、回避の消費が25から21になります。鐘の途中経過と住民の位置も保存します。
- 西の「白塩の段丘」と探索依頼「運び手の帰り道」。琥珀の森の西で伝言板を読み、北の岩棚か南の塩原を迂回して見張り場の取っ手を回収します。巻上げ機を直すと石門が開き、実際に通れる近道になります。帰還報告と報酬は一度だけで、開通状態も保存します。旅の記録からこの依頼を追えます。
- 石門が開くと、伝言を書いた運び手ナルが見張り場・貯水槽・谷側を往復します。開通報告の前後と章末の選択で会話が変わり、帰還報告後は谷側に荷が届きます。ナルの移動途中も保存されます。
- タッチ、キーボード、ゲームパッドの入力処理。タッチは移動・視点・操作ボタンを独立したpointerとして所有し、capture喪失・画面回転・非表示・BFCache復帰で残留入力を解除します。端末動作JSONには、生座標を保存せずに受理経路・同時pointer数・移動量・解除理由を集計します。描画品質、音量、視点感度、被ダメージ軽減の設定。
- 主人公、ミラとセナ、住民7役、兵・弓兵・獣・ボスと番兵4テーマを、成人比率と役別装備を持つ独自の関節モデルへ統一。材質別に束ねた骨格付き形状、地面を参照する足運び、移動距離に応じた歩行・走行、三武器の攻撃、回避・霊薬・被弾・回復姿勢・倒れる動きを実装しています。近くの木は枝と葉の塊、遠くの木は軽量形状へ切り替え、石・木・布・金属・土・水の表面と建造物・小物を更新。楽曲は独自の48秒・三層の合成音楽、移動・戦闘・UIは24種類の合成効果音と既存vault素材を使用します。写真計測モデル、顔の演技、実楽器録音ではなく、実画面・実聴・実機性能と指定10作品との品質比較は未確認です。

## 開発

Node.js 22.12以降または対応する新しい版を使います。この制作環境ではNode.js 24.19.0で確認しています。

```bash
npm ci
npm run dev
npm test
node scripts/verify-main-runtime.mjs
node scripts/verify-gathering-runtime.mjs
npm run test:vaults
node scripts/generate-vault-assets.mjs --verify
node scripts/verify-soundscape.mjs
npm run test:journey
npm run test:crossing
npm run test:forge
npm run test:session
npm run test:expedition
npm run review:saves
npm run review:combat
npm run compare:combat-priority
npm run compare:touch
npm run build
npm run package
npm run test:artifacts
```

開発サーバーはViteの出力するURLを開きます。通常環境でスマホ確認する場合は同じネットワークからPCのアドレスへ接続します。相談の新旧表示を同じ条件で確認するための [自動徒歩で生成した検証用セーブ](release/review-saves/README.md) もあります。通常の記録を先に書き出してから読み込んでください。戦闘表示と入力結果は [再現可能な戦闘比較記録](release/combat-replays/README.md) で同条件に揃えられます。production adapterの入力監査は [タッチ入力監査](docs/TOUCH_INPUT_AUDIT.md) に記録しています。いずれも実画面・物理タッチ・面白さの評価を代用するものではありません。

公開用の静的出力は `dist/`、外部依存が不要な単体版は `release/Q-ash-pilgrim.html` です。Sourcesと生成物を変更したら両方を更新してください。

制作は人間の準備を開始条件とせず、許可済みの自動工程で進めます。本番入口の開始・保存・中断復帰に加え、徒歩で獲得したsaveから相談UI・選択・SceneView呼出し境界・reloadまでを [自律検証工程](docs/AUTONOMOUS_VALIDATION.md) で検査します。これはNode内の明示した模擬境界による検証で、production SceneView / WebGL、ブラウザー画面・実機・音の実聴・人間の比較評価の証拠とは分けます。ChatGPT Workの監督付き環境では、上の一般開発手順から直接serverを起動せず、正式Sites手順に従います。

Three.js 0.186.0を固定しています。[描画にはWebGL 2が必要](https://threejs.org/docs/pages/WebGLRenderer.html)です。Vite 7.3.1を固定し、package-lock.jsonを管理しています。配信版ではThree.jsと3Dシーンを遅延チャンクへ分け、単体版ではネットワーク不要の1ファイルへ再結合します。ゲーム状態は60 Hzの固定ステップ、描画はrequestAnimationFrameです。多数の木・岩・草はInstancedMeshで描きます。この制作環境では実機のフレームレートは未測定です。設定の「この端末での動作」は、遊んでいる間のブラウザーの描画フレーム間隔を計測し、JSONで書き出せます。直近と全期間の遅延を分け、ソースの指紋・開始地点と視点・描画数、production adapterが観測したpointerの集計を記録します。「計測をやり直す」で比較を始められ、新しい旅・セーブ読込・設定や画面サイズの変更は別計測になります。

第三者のコードのライセンスは [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt) を参照してください。

以前のCC0人物素材の出所・固定版・加工内容は [素材記録](src/assets/characters/provenance.json) に保持しています。現行描画用の独自人物形状は [造形記録](src/assets/characters/detailed-provenance.json)、タイトル画は [原画記録](src/assets/title/provenance.json)、音楽と効果音は [音源記録](src/assets/soundscape/provenance.json) を参照してください。以前のGLBは資料として残し、現行配信には読み込みません。`scripts/prepare-characters.mjs` に記載の版から再生成できます。vaultの生成画像・音声は [vault素材記録](src/assets/vaults/provenance.json) と `scripts/generate-vault-assets.mjs` でbyte単位に再現します。配信版では同じassetを読み込み、単体版では埋め込みます。

完成期限は2026年9月20日です。完成条件と残る検証は [完成までの作業](docs/COMPLETION.md) に記録します。

配信用の作業ディレクトリは、容量を二重に使わないよう生成物へのハードリンクを使う場合があります。生成物は配信完了まで変更せず、再ビルドしたら `npm run test:artifacts` で作り直してください。
