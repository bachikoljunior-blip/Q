# 不変の風景のローカル変換 — 2026-09-14

基点は `0a657936f41580ff26f1f787d5c8f63535102d9d`。対象は `src/scene.js` の風景の変換処理のみ。ゲームルール、保存、素材、座標、形状、材質、影の設定、インスタンス配置は変更していない。

## 原因と採用した変更

固定された Three.js 0.186.0 の `Object3D.updateMatrix()` は position / quaternion / scale からローカル行列を再合成し、毎回 `matrixWorldNeedsUpdate` を立てる。`WebGLRenderer.render()` は通常 `scene.updateMatrixWorld()` を呼ぶ。Scene 自身も既定では毎回更新するため、子孫への `force=true` が伝播する。

そのため **ローカルの自動更新を止めても、ワールド行列の乗算と木構造の走査は減らない**。今回はそこを変えず、完成した不変の風景だけで `updateMatrix()` を一度実行し、`matrixAutoUpdate=false` にする小さい代案を実装・比較した。`matrixWorldAutoUpdate`、Scene の既定設定、Three.js の更新メソッドは変更しない。親の移動・回転・拡縮は通常の上から下への更新で反映される。

対象は地形、遠景の山、植生、水面と橋、荷車・テント・分岐後の物資、家、灯火の石造建築の **273ノード**。生成順・親子関係は維持し、屋根や車輪等の初期回転を設定し終えてから処理する。草・水の時間uniform、草の描画個数、物資の表示切替はそのまま更新する。

Scene 全体、空、雲、冠の輪、灯火の炎・回転輪・光・光柱、人物と骨格、敵の予兆、矢、収集物、粒子、斬撃、効果、カメラ、太陽とその注視先、村・西部・相談の各表示は一括処理の対象外。共用 `mesh()` に自動固定を入れていない。

ワールド行列自体を固定する案は親の変更に追従しないため不採用。独自の更新キャッシュも、強制更新・dirty状態・将来の子変更の契約を広げるため今回実装しない。独立した読み取りレビューも、ネイティブなローカル更新だけの変更を推奨した。

## 注意点・所要時間・採否

Three.jsの手動ローカル行列の契約が残る。今後この273ノードのposition/rotation/scaleを編集する場合は `updateMatrix()` を呼ぶか、対象を焼き込みから外す。0.186.0の `updateWorldMatrix(true,false)` は更新した祖先のforceを、dirtyでない子へ伝播しない。したがって親を動かした直後、通常の上から下へのworld更新前に子だけの `getWorldPosition()` 等を呼ぶ用途の等価性は保証しない。現行 `src` にその呼出しはなく、ここで検証したのは実際のrendererの更新順である。
