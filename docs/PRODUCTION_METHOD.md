# 制作方法と期限の見直し

完成期限は2026-09-20、品質目標は指定10作品に劣らないこと。目標・期限は変更しない。

## 毎回の判断

継続状態を確認した直後・次の制作項目を選ぶ前、mainへ反映する前、新しい阻害事項が出た時に次を記録する。監視側も継続確認直後の読み取り評価を行い、実行中の制作への重複起動・並行書込みを避ける。

1. 完成条件のどの不足を埋めたか。実装と、実際に遊んで確かめた結果を分ける。
2. 残作業を具体的な制作単位へ分け、直近に完了した同種作業の所要時間で見積もる。実績のない領域は未見積もりとし、都合のよい速度を仮定しない。
3. 許可された実機・画面検証の待ちを含め、期限までの工程を再確認する。工程が成立しない、または成立するか分からない場合は、今の方法・優先順位・調達・確認手順を疑う。
4. 代案を一つ選び、実際の成果物で試す。制作時間の短縮と品質を別々に比較し、採用・改修・撤回の判断を残す。
5. 期限内の達成見込みが立ったかを更新する。テスト数、更新回数、コード量を完成の代理にしない。

判断は「見込みあり」「現行方法では届かない」「根拠不足」を区別する。現行方法では達成できない、または達成できるか分からない（根拠不足）と判断したら、どちらもやり方や前提が間違っていることを疑う。根拠不足の場合は判断できない原因と不足する証拠を特定し、それを解消する調査・測定・実装比較を次の優先作業へ反映する。同種作業の所要時間、手戻り、品質の検証結果を分けて測り、期限判断を更新する。不明の報告だけで現行方法を継続可と扱わない。根拠不足を不可能や順調へ読み替えず、不足する見積もり・検証を次作業の選択に反映する。方法変更は実装・比較・採否の結果まで残し、宣言の追加だけを改善と扱わない。

## 2026-09-14：人物制作の方法を変更

従来は人物の形状と四肢の振りをその都度コードで組み立て、生活行動を追加するたびに表示側も個別に増やしていた。近接で見える造形、関節の動き、人物ごとの動作の差に対して、部品を少しずつ足す方法の効果を実画面で確かめていなかった。

今回試した方法は、利用条件を確認した既存の骨格付き素材を取り込み、必要な動作だけを共有する制作工程。Kay LousbergのCC0素材を固定コミットから加工し、人物3種類・18動作と取り込みスクリプトを用意した。プレイヤー、ミラ、セナ、近接兵を同じ制御に接続した。元の作者、ライセンス、原本と加工結果のハッシュを記録し、このプロジェクトの自作モデルとは扱わない。

## 現時点の見通しと次の検証

期限内に品質目標へ到達する工程は、まだ根拠付きで成立していない。人物制作の共通化は一領域の方法変更であり、複数地域・物語・演技・音響・実機調整の残量と制作速度は未見積もり。これらを残したまま単なる小機能追加へ戻らない。

| 課題 | 次に試す方法 | 採否を決める確認 |
|---|---|---|
| 造形と動き | 同じ素材工程で役割・装備・人物差を制作 | 近接、歩行、剣槍大剣、回避、会話の画面比較。動きの不一致は修正してから展開 |
| 大量の個別コード | 地域・遭遇・会話のデータを制作単位へ分離 | 新しい場面を追加した所要時間と、既存進行を保てた証拠 |
| 実画面確認が止まっている | 同じリポジトリを正式な監督付きプレビュー／許可されたiPhone・Androidで確認 | 下記の画面・操作記録。別URLや別ブラウザーでアクセス拒否を回避しない |
| エンジン選択が未比較 | 現行構成とUnity/Godot等の制作工程を比較対象にする | インポート、1場面制作、スマホ配布、保存継続の実測。名前だけで移行を決めない |

正式プレビューの状態確認は、依然サービス不在。復旧用のSites手順では、利用側でサービスを起動・置換できないと確認した。必要なのは動作する監督付きプレビュー、または許可された実機からの記録であり、テストを追加して解消したことにはしない。

最初に確認する場面：新規開始と続行の読込、保存ファイル読込、プレイヤーを前後から見る、各武器の三段攻撃、回避、霊薬、途中保存の再開、ミラとセナの会話、兵の予備動作と命中。縦横の画面、複数指、音の開始、描画時間と30分継続も別途確認する。

この作業順は完成範囲の縮小を意味しない。評価結果が悪ければ素材や制御を差し替え、期限への見通しと方法を再び見直す。
