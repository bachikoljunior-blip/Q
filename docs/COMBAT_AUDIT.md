# 独立した反例による戦闘表示の修正候補

2026-09-14。基点 main: 5b2ede88a7d08ae7c271a305cf015c55fdf33d9e。

独立した読み取り監査で、実際のGameの被弾と本番HUD関数への出力を比較した。逆向きと射程外の兵士、頭上と壁で止まる矢、古い固定警告による緊急攻撃の隠蔽を再現した。追加比較では外れる固定照準の弓も誤警告していた。予測式をそのまま正解にする検査を取り除き、実際の接触結果と本番表示関数を判定基準にする。

## 修正候補

- 攻撃側と予測側で、近接の射程・向き・高さ・遮蔽物と、矢の最初の衝突計算を共有する。
- 弓の固定照準と到達時間を用い、現在の巡礼者位置へ当たらない矢を除外する。将来のプレイヤー移動は予測しない。
- 現在の二つの危険を優先表示し、過去の衝撃波イベントで1.8秒間上書きを止める処理を除去する。
- 受け流し受付後に攻撃長押しが防御を解除する既存不具合を修正。低優先度の攻撃は受け流し中に開始しない。

## 比較と方法の採否

選んだ9条件では、旧版6条件の警告／本番HUD出力の不一致が候補で解消した。両版の実ダメージ結果は同じ。弓の予測0.806秒に対して被弾は0.833秒、飛翔中の矢の予測0.232秒に対して被弾は0.233秒。60 Hzの離散処理による差を含み、精密な未来予測とは扱わない。攻撃長押しと受け流し、遮蔽物の後の二危険、寿命の最後の一ステップもV8で再現した。

最初の修正案は全48本の遮蔽物を毎回精査し、同一ホストV8の2,000回比較で26,134 msを要した。旧版225 msに対する後退なので、その方法は不採用。候補を安い接触計算で並べ、表示する二つの危険が決まるまで遮蔽物を調べる方式へ変更し、同条件で1,265 msになった。これも旧版より重く、端末性能を改善した証拠ではない。全て遮られた場合は候補を多く調べるため、今後の負荷確認が必要。

元のNode環境では旧版の監査まで実施できた。その後、環境のsandbox起動処理がENOSPCで失敗した。新旧の比較はGitHubの正確な純粋JSソースを取得し、functionsのV8上でimport/exportのみ接続し直して実行した。DOMは文字列を受ける最小の代替。通常のNode試験、ブラウザー描画、タッチ、音、実機、外部プレイヤー評価とは区別する。通常試験とビルドは既存GitHub Actionsで確認する。

再現: `node scripts/compare-combat-outcomes.mjs` と `npm test`。比較結果は `release/combat-replays/contact-comparison.json`。画面評価、地面すれすれや橋端での長い予測線と60 Hz実衝突の一致、移動中の複数攻撃、実機負荷は未確認。品質目標や2026-09-20期限を下げず、期限内完成の判断は根拠不足。


## 60 Hzの実衝突順序へ合わせる変更 — 2026-09-14

一回の長い線分で地形・橋・人物を調べる予測を、実ゲームの矢と同じ60 Hz刻み、寿命減算、地形・障害物・人物の衝突順序で進める読み取り専用コピーへ変更した。候補の安い人物交差と「表示する二件だけ詳しく調べる」上限は維持する。予測入力とゲーム状態は変更しない。

橋二本について、橋幅の内外・傾斜開始点・路面境界と、橋の縦境界を跨ぐ120軌道を生成した。各軌道は警告を得た後、同じGameを60 Hzで最大120フレーム進め、警告の有無と実際のhurtイベントが一致すること、予測前後で矢が不変であることを検査した。GitHub Actionsの同一ジョブではこの検査が2,371 ms、全111試験が4,239 msで成功。主章・副依頼・30分保存継続・両遠征路、ビルド、配信用成果物検査も成功した。単体版の追跡ファイルは変更前のため、最初のCI全体は最後の一致検査だけ失敗し、生成物を保存した。

この測定はホストNodeのロジック時間であり、スマートフォンのフレーム時間ではない。矢ごとに最大108小区間を調べるので、全候補が遮られる状況や多数の矢での端末負荷は未測定。実画面、カメラ外からの方向理解、移動中の複数攻撃、タッチ、音、物理端末、外部プレイヤー評価も未確認。採用条件は、追跡単体版を再生成して通常CIを全て通し、次の実機・複数敵比較で表示利益に対する負荷を確認すること。
