# 顔micro3型の独立技術レビュー

対象は作者cloth資料ではなく、別担当作成の `mira-face-patches-F01-F05-F09-v2.png`。元head/full画像と合わせて `view_image` で実見し、作者manifestと原PNGを読み取った。作者の自己評価を採点根拠としていない。ブラインド評価とは称さない。

**判定：3型の大まかな曲面を説明する補助資料として条件付きで保全できる。正確な型形状/共有辺の確定、完成顔へ接続可能な3D部品、実顔一致の合格にはまだ使えない。** 今回新規生成・編集・造形・runtime・remote変更は0。追加の試作を広げず、このレビューで閉じる。

## 単体形状の読み取り

| ID | 独立に確認できた形 | 条件と不確実性 |
|---|---|---|
| F01-L | 額の広い浅い凸面、眉側へ向けた下縁の曲がり。穴のない小さい1パッチ | FRONTとPROFILEの表示倍率が揃っていない。深さ/曲率を画像px比から決められない。眉/こめかみ/頭皮側のどの辺が共有されるか未定義 |
| F05-L | 外上側のmalar ridgeから下側hollowへ続く、額より非対称な面 | 1つの滑らかな制御曲面で表す形の候補にはなる。ただしridge位置と凹面の深さは元顔へ未登録。眼下縁/鼻側/下頬への接続は絵だけでは確定しない |
| F09-L | 下頬から顎輪郭へ回る細長い屈曲面。輪郭とPROFILEの曲がりは額/頬と異なる | 顎角の裏への巻込み量と首側の接続は未確定。画像の裏箱を顎の厚い別物体として作らない。元headの側面/顎下 viewへ登録して初めて位置を固定できる |

三者を全て同じ球片に置き換える根拠はない。一方、画像に制御点や対応する断面はなく、特定の3×3/4×4ネットで十分近づけられた実証もない。「1つの滑らかな曲面として検討できる」は形状分類の判断であり、短時間制作の実績や正確な再構成保証ではない。

FRONT/PROFILE/BACK/3/4は各行にあり、PROFILEは明らかに細く、3/4も横幅が短くなっている。作者v1→v2変更のpixel保持は今回の検査対象でなく、同じ実3Dをカメラで回した画像だとは証明しない。

## 具体的な未確定点

1. **共通スケール/軸がない。** 元1448×1086画像で目視した概略bboxはF01 FRONT高さ約179px、PROFILE約253px（約1.41倍）。F05は約239/246px、F09は約211/225px。bboxは数pxの目視幅を持つ補助観察で、厳密な画像抽出結果ではない。特にF01の差は、同じ縦寸法を同じ倍率で示す図として直接トレースできないことを示す。形状自体が必ず矛盾するとまでは断定しないが、異なる倍率を補正せず厚みを作ってはいけない。
2. **辺の対応を示していない。** 額の上辺/下辺や頬の尖る側は大まかに読めるが、各viewの同じcorner/edge IDがない。BACKは左右反転した形に概ね対応するものの、projection/edgeの正確な一致は未検証。全4視点に1対1で対応する輪郭点の台帳が必要。
3. **manifestのjoinsは直接weldするedgeではない。** F01のjoinsにF05があるが、locator上では額と頬の間に眉/眼周囲領域があり、両パッチは接していない。これは作者も「conceptual neighboring regions」と記載した概念隣接としてのみ扱える。将来そのまま額と頬をつなぐと眼周囲を飛ばす。F03/eyelid/brow等を含む接合graphへ具体化する必要がある。F09→chin/neckもどの辺かまだ指定されていない。
4. **locatorは本人左右の証拠に限定する。** 三つの枠は正面顔の画像右、本人L=+Xにあり、footerとmanifestに整合。元fullの本人右の杖は正面画像左にある。ただしlocatorは生成された別描写なので、顔の細部/曲率を元headからpixel一致で転写した証拠ではない。完成顔の形は原head/fullを正本として保つ。
5. **材質/縁を造形へ誤転写しない。** 厚い縁、裏の囲い、粒状模様は切断パッチを読ませる図示表現として扱う。顔runtimeへ貼る肌素材、均一な皮膚厚、全境界のベベル/溝を追加する指示ではない。必要なのは露出する連続面と共有境界である。

## 次工程への限定された受渡し

保存できるのは、F01/F05/F09の部位概念、本人Lの配置、異なる大まかな曲面傾向、4方向の参考像まで。55×55×25、40×35×40、38×35×45mmは作者の仮envelopeとしてそのまま識別し、板厚・校正済み曲率・最終寸法にはしない。

実装前の台帳では、局所軸と各viewの対応corner、元顔へ登録する範囲、隣接edgeの順序/共有点、法線の接続を1つにする。UVやskinweightも同じ境界へ結びつける。眼/瞼/口/鼻の隣接と首cutは別partsとの組立て段階で検証する。画像にない穴や二重皮膚を補う方式にはしない。現段階で画像を再量産したり、この3型だけを完成顔と扱う必要はない。

## 保存根拠と測定境界

作者manifestの8filesと原head/full2filesのbyte/SHAを独立照合し一致。候補PNGの全decodeを確認：1448×1086 RGB、1,593,624B、SHA256 `bdb78e0536808201b80aca8d1c8505faaec13c88a1577b65d93570a261b56049`。機械checkは約0.105秒で、視覚レビュー時間や3D制作時間ではない。

`audit.json`に全input hash、目視概略bboxと測定の限界を保持。`check.py`は読取/数値記録のみで画像を編集しない。新しい実geometry、UV、骨、GPU、WebGL、表情変形、ゲーム画面/顔の自然さ、実機/PS4品質は検査していない。既知未完了toolは0。
