具体的な残る画像矛盾は AH07、AB01、AB03。該当 sheet は 1 回の限定修正を既に使用した。修正を繰り返して矛盾を隠さず、今回の資料範囲を固定する。他の型も「形の参考」の条件付き選択であり、全角度の同一形状、閉曲面、共通辺の一致を画像で証明したわけではない。全体台帳担当へ不足を引き継ぎ、全人物資料が揃う前の局所 3D 追加はしない。

左右は本人 Right = actor −X / hand-0 / 正面画像左、Left = +X / hand-1。固定画像を反転していない。右手は杖を握る完成像、左手は開いた/緩めた像を基準とする。生成した単独指節は開いた形の説明であり、組立済み握り姿勢ではない。左への再利用には解剖学的な輪郭・巻方向・法線・骨登録が必要。

手首境界は R/L-wrist（AH10）から cloth:F01-R/L・F02-R/L の下端 WRIST へ対応する。S05/S06 は袖、F03 は巻革であり AH10 に複製しない。AH10 の旧 hand-local Y −15..9 mm は登録案だけで、袖口開口・重なり長・動作中 clearance は未定。肌同士は共有位置/重み/法線、布と肌は別層の重なりとして扱う。

靴上端は R/L-boot-shaft・boot-rim（AB07/AB08）。旧 foot-local Y 340 mm / knee-local Y −95 mm を参照点にするが、全体台帳ではズボンの微小 leaf 所有が欠落しており、相手 ID を架空に追加しない。長い上着の裾をズボン下端と代用しない。ズボン裾の共有輪郭、靴内への重なり、脚 clearance、knee/foot 重みは未定。`ASSEMBLY_BOUNDARIES.json` が具体的な対応と null の未定値を保持する。

原生成 PNG、13 個の正確な prompt、返却時刻、原出力 path、hash を保存した。旧 3 計画ファイルは byte 不変で保持し、その generated=0 は作成当時の状態として扱う。現在の台帳は `TYPE_REFERENCE_COVERAGE.json`、全 call は `GENERATIONS.json`、計時は `TIMING.json`。同時 call の時間和は作業経過時間ではない。画像は OpenAI 生成の外観資料であり、CC0 写真、CAD、実 3D、ゲーム画面、実機/PS4 品質の証拠ではない。

固定後の読取確認は `python verify-record.py`。元の一時出力が残る環境では `--external-inputs` を付け、原 PNG とコピーの全 byte 一致も確認できる。`finalize-record.py` は metadata を作成した記録であり、固定後の検証には再実行しない。これらの確認は hash/配置/出所の保全に限り、画像採否の自動判定ではない。
