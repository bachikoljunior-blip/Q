## 枠のTOP

v2のTOPは投影された線の両端に座があった。v3ではWIDEの左、DEPTHの下の各1箇所だけが座として残り、反対端は曲がったリボンの外側の足跡になっている。上端と下端が同一平面内で上下に並ぶ弓の、上から見た位置関係として解釈できる。

これは指定された局所矛盾の解消である。別panelの大きさをそのまま同一縮尺とみなさず、TOPの座の角数や寸法をnative形状へ転写しない。既存nativeのテーパ端と原画の箱に近い端の差を消したわけではない。新たな裏面や接合断面まで確認できたとも扱わない。

## S05の比率

読み取ったPNGは1536×1024。灰色背景と茶色い帯の色差を3閾値で区別し、目視で指定した各panel範囲内の色付き画素の外接矩形だけを数えた。原画像のcrop/resize/retouchや別画像の書出しはしていない。

| bitmap上の見掛け比 | 3閾値の範囲 | 生成依頼の設計目安 |
|---|---:|---:|
| OUTER/INNERの長さ÷幅 | 約34.6–36.3 | 約43 |
| ENDの幅÷厚み | 約3.40–3.46 | 約5 |

この数は画像上の範囲であり、革の実寸法ではない。丸いedge・模様・影を含むため誤差がある。特にSIDEの色付き高さは11–14画素と薄く、数画素の境界差が比率に大きく効く。SIDEとENDが「絶対に異なる立体」を描くという厳密な証明にはしない。

それでも、依頼された43:1、5:1を満たした精密投影図だと認定する根拠はない。5角度の原画の存在と直線薄帯の形状参考は受領できるが、正確な比率・完成した巻き配置については未固定を残す。材質模様や光の見え方を実際の革材質の再現性と混同しない。

## native組立対応の来歴と単位修復

`STAFF_ASSEMBLY_MAPPING.json` の19配置・24内部関係を読取った。最初の版は coordinateFrame を millimetres と書く一方、nativeMatrixWorldの移動量はThreeの1.556等のメートル値だった。統合担当へ報告し、原数値を変えず、行列の移動量はmetres、boundsMmとnominalYmmはmillimetresと明示する修復を受けた。

- 修復前 SHA256: `6910cd3e5e7974e5f7cb8c3d6f04fffaf7e6c5303d26182f33d57eecb854e4e0`
- 修復後 SHA256: `2858b0f90574d3652d6c26fbf34cc9f259ab58d83fe24012c0786360c5391a99`

固定commitの既存 `parts.json` と19行列を全要素で照合して一致。既存頂点をその行列で変換し、mm換算したboundsも全19件で差0。24関係の両端IDはすべて実在する。これは原byteから来歴と単位を確かめたもので、画像から寸法を測ったものではない。24件すべてがweld、無交差、荷重支持、人物への取付を証明するという意味でもない。実把持の人物変換は未定である。

単位の必要修復は閉鎖した。新原画は上記範囲の条件付き資料として保存できるが、精密投影と全人物資料完備の判定は残る。新造形の開始、実WebGL、ゲーム品質、自然さ、PS4相当、端末性能の合格を与えるレビューではない。

`check.py` / `RESULTS.json` に必要な再現読取を保存。既存メッシュを再生成・変更せず、原JSONと原画像だけを読んだ。
