# 衣装全型の画像資料 — v64 有限固定

新規37枚の生成・実見を終え、旧34型79配置と不足6型17配置を合わせた **提案40型96配置** の画像・組立対応を保存した。画像が無かった型は全て画像を持つ状態になった。これは生成画像の全パネル整合、全人物の資料完備、実3D完成や採用を意味しない。今回の新3D、本編変更、remote書込みは0。

## 固定した成果

- 初期3型sheet10枚、初回の単型修正9枚、不足型初回6枚、不足型修正4枚、残る具体欠陥の初回修正6枚、TR01/02の別方式比較2枚。全37call終端、未完了0。
- `RAW-ASSETS.json` の37原PNGは68,383,160 bytes。各生成元からのcopyをSHA256・全byteで照合済み。画像の切抜き・合成・サイズ変更・Python編集は行っていない。
- `COVERAGE.json` に40型、96配置、選択画像、旧独立レビューの有無、条件、左右の対応を保存。`ASSEMBLY.json` に31個の意味上の接合契約を保存。数値的に閉じた共有頂点・UV・weight配列はこの資料工程ではまだ作っていない。
- Right=-X / Left=+X / front=+Z。正面のRightは画像左、背面のRightは画像右。旧B02-R/B03-hanger-RはIDを残し、完成像に従う本人Left(+X)への配置訂正案を別欄に記録した。
- 原P04-RBはP04の後部subsetであり、全P04を覆う証拠へ昇格させていない。旧T01/S05/P01の条件付き独立確認と、今回作者による実見は区別した。

## 生成方法の実結果

最初の6枚では、閉じた袖筒、全カウル、左右両方の前裾など、単一小面の指定が全服へ補完される例が繰り返された。単型に分け、存在しない壁、自由端、折れ回数を具体化した修正では、S06の開放半面、P04の単一肩曲面、W01/W03の一折れ、L01/L02の単一半面、L03の一面化、F04の薄い凹面断面が読めるようになった。これは形の種類が伝わったという作者所見であり、実数の表面適合検査ではない。

TR01/02は脚と完成衣装を添えた初回、失敗画像を編集するv2の双方で足首の閉じたリムが残った。v2を棄却のまま固定した。次の方法Bでは参照画像0、人物・服・装着小図を取り除き、一枚の開放した湾曲布だけを主体にした。両型とも4視点で両長辺/短辺が開いた曲面として読め、閉筒の描写が消えた。青灰色は形状検討用であり、完成像の茶布色に置き換える根拠ではない。実股形状への登録、TR03の4辺との適合、脚全長の曲率は依然作者設計の未確定項目である。これを画像番号だけで解消したとはしていない。

TR01/02方法Bの2callは同時開始、pair終端まで約47.8秒。これは画像生成の壁時計時間で、完成3D制作時間ではない。

## 残る具体条件

1. **S03** は単一折れの位相は一致するが、画像は旧180×90mmの作者案より縦長。未校正の倍率/曲率登録として残す。画像から短い帯の厳密寸法を得たとはしない。
2. **F03** の旧locatorは前後で左右が違い、修正版は位置強調が曖昧。単体リボンの図は利用候補だがlocatorは除外する。完成像と96配置表のRight=-X/Left=+X、巻き順を正本とする。
3. **T02** の生成文「left shoulder」は後面の画像右locatorと矛盾する。文言を除外し、完成像と台帳を使う。**T04**の生成HOODIE表記も不採用、正しい隣接はARMHOLE。
4. **C01/W03/L02** は角度・各layerの個別強調が未計測/不十分。色模様や厚い切断縁をruntime形状/材質へコピーしない。共通の渦模様は完成正本の控えめな布に反するため不採用。
5. **TR01/02/03** の股上領域の共有所有・長さ、**TR04** の四つの布帯端、**TR05** の靴内overlap、**PH01** のcape裾曲線/隣接端は意味上の対応のみ固定。TR03に股を二重所有させず、TR04を革B01に流用せず、PH01を独立cap付きsolid6本にはしない。
6. 既存P01中央はx=±5mmの10mm空白を持つ。画像台帳だけで閉じたと扱わず、将来共有辺の所有者・位置/UV/weight/time解を一つに定める必要がある。以前の死亡床侵入や支持CPU問題もこの画像工程では未修復。

これらを考慮した単体形状の条件付き資料として引き渡す。全体の接合正本が画像だけで完成したとの判定はしない。画像をCAD精度まで繰り返し生成する作業も行っていない。必要な数値登録は作者仕様として別管理する。

## 記録と限界

`CALLS.json` / 各prompt.txtに入力と出力を保存。サービス内部jobIDは公開されず、raw出力UUIDと開始/終端時刻を追跡した。S06修正だけは圧縮前の呼出入力path配列が残らず、promptに書かれた第2canonical画像のexact pathを確認できないため、完全入力receiptとは称さない。原PNG/prompt/time/hashは保存済み。他36callは保存した入力pathとpromptを保持する。

`TIMING.json` の固定時点で総経過約59.3分、生成call時間合計約33.8分、同時実行重複を除いた生成中の時間約25.8分。残りには仕様/読取/実見/連絡/保存が混在し、それぞれの独立stopwatchは無い。3D造形時間0。生成成功や図の実見をPS4全画面品質、WebGL、自然な変形、iPhoneSE3性能の測定には使わない。

新しい型・画像・3Dへ拡張せず、全call終端のこの有限資料を独立台帳レビューへ渡す。
