# 相談表示を同じ条件で比較するためのセーブ

`npm run review:saves` が、新規ゲームから自動操作で徒歩・戦闘・鐘・配達を達成して生成する検証用の記録。人間のプレイ記録ではない。瞬間移動、体力の書換え、無敵化、進行フラグの直接変更は使わない。

既存のタイトル画面「セーブファイルを読み込む」から使用する。手元の通常セーブを上書きしないよう、先に「旅の記録」で書き出して保管する。

| 接頭辞 | 場面 |
|---|---|
| hearth | 集落の「炉を囲む約束」 |
| road-watch | 街道の「夜道の目印」 |

| 末尾 | 比較する状態 |
|---|---|
| ready | 依頼達成後、相談を始める前。人物のしるし・案内を確認 |
| middle | 二つ目の発話。話者、進み具合、既読一発話の読み返しを確認 |
| medicine / tools | 集落の各選択を完了。結果の会話と装飾、案内終了を確認 |
| light / rest | 街道の各選択を完了。結果の会話と装飾、案内終了を確認 |

同じ記録を旧版v0.12.0と新版で読み込み、同じ端末・画面向きで比較する。記録には将来の選択を自動決定する命令はない。新旧で相談の発話番号・報酬・住民の位置が一致することを先に確認する。

実画面の確認事項：相談への気づき、話者の識別、読み返しの可読性、指での選択、操作との重なり、無音での理解。描画・音・タッチ・端末性能・外部評価は、このファイルの生成だけでは検証できない。

## 同じ端末での動作比較

1. 通常のセーブを保管し、比較する両版で同じ `hearth-ready.json` を読み込む。同じ端末、画面向き、音・加護・画質設定を使う。入力装置と端末名・OSは別途記録する。
2. 同じ視点と移動経路を決め、設定の「計測をやり直す」から再開する。まず同じ時間（例：60秒）を比べ、安定性は別に30分の探索と戦闘で確認する。場面間の操作差を記録し、異なる経路の結果を同一条件と扱わない。
3. 設定を開いて「動作の記録を書き出す」。報告にはアプリ入力のSHA-256、開始時の位置・視点・ゲーム時刻、正規化した開始セーブのSHA-256、終了条件、最後に採取したプレイ中の描画数が入る。元セーブ自体は含まないため、使った検証セーブを別に保持する。SHA-256を計算できない環境ではセーブ指紋は欠落し、そのまま未取得と扱う。
4. `frames` の直近窓と `frames.session` の全期間を分けて比較する。全期間の95%点は1 ms刻みの上限値で、1000 msを超える区間は最大値を上限とする。全期間の遅延数と最大間隔は窓から消えない。描画数は直近30フレーム以内の一標本であり、平均やGPU時間・メモリバイト数ではない。

アプリの指紋はゲームのソース・素材・依存定義・ビルド設定を識別し、Gitコミット・文書・生成日時とは独立する。新しい旅、セーブ読込、設定や画面サイズの変更は別計測にする。休止・非表示の前後を跨ぐ間隔は除外する。フレーム間隔だけからタッチ遅延、実際に画面へ提示された枚数、音質、面白さを判定しない。
